1

Three tabs, not five. Insurance owns two processes, so the bar carries exactly what the role uses. Tab sets are built from GET /api/me/capabilities at launch — padding the bar to five with dead destinations is how enterprise apps start feeling hollow.

2

Grouped by pressure, not by date. Overdue / Due today / This week is computed server-side from statusChangedAt against the active SlaRule — the same rows the SLA engine is about to send reminders about.

3

Buttons come from the server. Each card renders availableActions for that record and status. When an admin edits the ownership table, these buttons change without an app release — and the client never holds a permission rule.

4

The stripe carries severity so the queue reads at arm's length; the chip carries state. Colour is never the only signal — the age line spells out the number of working days, honouring the Fri/Sat calendar.

5

Swipe right takes the primary action; swipe left opens the reason sheet (Plate 04b). Destructive and reason-bearing transitions never fire from a swipe alone.

The SLA strip is the headline because it is the only thing on this screen with a deadline attached. Each tile opens the Work queue pre-filtered — a number you cannot act on is decoration.

2

One chart, and it is a funnel because the lifecycle genuinely is one. Segments are tappable into a filtered Directory. No pies, no sparklines: the API returns point-in-time aggregates, so a trend line here would be fiction.

3

Expiry buckets come from four indexed COUNT queries added in the reports rework — cheap enough to load on every app open, and cached 30s server-side.

4

1

Overview is a triage screen, not a data dump. It answers "what is wrong with this person's file" — processes, employment facts, and an Attention block that pulls forward the two things with deadlines. Everything else lives one tab away and loads lazily.

2

Salary is masked by default and revealed behind biometric re-auth. The API already strips it for roles that shouldn't see it — the mask is the second lock, for shoulders.

3

The camera button is the mobile-only feature that pays for the project. Point it at an Iqama and POST /api/ai/extract-document returns number and expiry, pre-filling a tracked document. It exists in the backend today and needs no new endpoint.

4

The action bar holds one primary verb, chosen from availableActions. The remaining transitions live in the overflow — a phone screen with six equal buttons is a screen with no recommendation.

1

The stepper is the record. Six nodes, one per status, with the actor and date that the audit log already stores — so the screen doubles as the file's history.

2

The gate is shown, not hidden. Unreturned custody items block the notice step by business rule; the disabled button plus a plain-language explanation beats a button that fails with an error after you press it.

3

Returning an item is inline. The most common action at this stage is ticking assets off — it should never require a second screen.

4

Finance sees a different bottom bar. The same screen, with Close instead of Send — again from availableActions, not from a role check in the client.

1

Unread is a tint and a bar, not a dot. At a glance you see how much is unread by how much of the list is coloured — a dot makes you count.

2

The monospace footer is the deep link. Category, entity type and time come from entity / entityId, which the notification table already stores — so every row can open the exact record with no new backend work.

3

Foreground uses the existing SSE stream; background needs Firebase and a device-token table. This is the one feature that turns an SLA reminder from an email read tomorrow into a hold cleared in thirty seconds.

4

Copy is written for the person, not the system. "Contract approval overdue" — never staff.record_stalled. Template keys stay server-side.
